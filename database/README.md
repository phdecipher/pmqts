# PMQTS database

## Local XAMPP setup

1. Start MySQL in the XAMPP Control Panel.
2. Open phpMyAdmin, select **Import**, and import `database/schema.sql` (or run it with the XAMPP MySQL client).
3. If `tbl_inventory` already exists from the previous setup, also import/run `database/migrations/20261006_add_inventory_qr_tokens.sql` and then `database/migrations/20261031_inventory_details_locations_custodians.sql`. These add the QR token column, the acquisition/disposal fields, structured locations (`tbl_locations`: department, building, room) and custodian history (`tbl_custodian_history`) without removing inventory rows. Administrators add locations from the **Locations** page in the sidebar; assets cannot be saved until at least one location exists. Then run, in order: `20261031_add_maintenance_pull_out.sql`, `20261031_add_requisitions.sql` (requisition workflow and job orders) `20261031_add_countable_assets.sql` (optional quantity for countable assets), `20261031_add_user_full_name.sql` (complete names for user accounts; existing accounts default to their username until edited on the **Users** page) and `20261031_add_asset_approver.sql` (per-asset approver) and `20261031_add_requisition_lines.sql` (several items per requisition) and `20261031_add_requisition_line_approval.sql` (each item is approved or rejected by its own assigned approver) and `20261031_add_requisition_borrow_until.sql` (date until which the assets are active). Then run `20261101_borrow_until_datetime.sql` (adds a time of day to that date) and `20261101_add_requisition_borrow_from.sql` (start of the active period). Finally run `20261101_add_requisition_return.sql` (remembers where assets came from so maintenance can return them after the active period). Then run `20261115_add_requisition_reports.sql` (damage and disposal reports filed while returning assets).
4. The scripts create `pmqts`, `tbl_inventory`, `tbl_maintenance`, and `tbl_users`. They use `CREATE TABLE IF NOT EXISTS`, so existing tables and procurement rows are preserved. The existing `tbl_procurement` table is expected to contain `id`, `pr_number`, `item_name`, `source_trigger`, `estimated_cost`, `status`, and `created_at`.
5. Open `http://localhost/pmqts/pages/setup_admin.php` and create the first administrator. The setup page stops accepting account creation after the first user is added. Passwords are stored as PHP password hashes.
6. Sign in at `http://localhost/pmqts/pages/login.php`. Dashboard, inventory, maintenance, procurement, QR label, QR scanner, and equipment record pages require authentication.
7. By default the PHP app connects to `localhost:3306` as `root` with an empty password and database `pmqts`. Override with `PMQTS_DB_HOST`, `PMQTS_DB_PORT`, `PMQTS_DB_USER`, `PMQTS_DB_PASSWORD`, and `PMQTS_DB_NAME` environment variables if your local credentials differ.

Inventory and maintenance CRUD, procurement requests/approval, dashboard metrics, and sign-in use MySQL. Procurement approval inserts an inventory row and changes the request status in one transaction. QR labels point to asset records using persistent random tokens; the scanner accepts a code only when its token exists on an active inventory asset.

Roles: administrator (`admin`), property custodian, teacher, department head, approver, maintenance personnel, procurement personnel and security personnel. Administrators manage accounts and roles from **User Accounts**; page access per role is defined in `ROLE_ACCESS` in `config/app.php`. No schema change is needed, since `tbl_users.role` is already a free-text column.
